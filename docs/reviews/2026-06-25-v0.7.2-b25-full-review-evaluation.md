# v0.7.2-b25 Full Review Evaluation - 2026-06-25

## Scope

Evaluated `docs/reviews/2026-06-25-v0.7.2-b25-full-review.md` against current `HEAD`
(`068d9704f115eab3a25850b84c45a513b551d355`), current review artifacts, and the living product docs.

This evaluation is a triage of the full UX/product review. It is not a repeat of the narrow release
delta code audit in `docs/reviews/2026-06-25-v0.7.2-b25-code-audit.md`.

## Verdict

The review is materially accurate and useful. It should be treated as a roadmap and priority review,
not as a blocker against the already-reviewed v0.7.2-b25 patch.

The strongest verified claims line up with source:

- P1 is improved but not fully complete: the WebView edge band is still a 4 DIP owned resize band.
- P4 is not implemented as a dock/undock behavior: `Show popout` activates the existing popout only.
- Return state still lacks popout-side paused state, volume, mute, and playback rate.
- P3 opacity is whole-popout layered-window alpha, so it affects video content too.
- P7 `soft` and `round` both map to the same native DWM outer corner mode.
- P5 has no explicit Fit / Fill / Cinema Padding viewing model.

## BS Check

No blocking BS found.

The review's weak spots are scope and decision framing, not factual accuracy:

- **Screenshots:** the review correctly warns that the screenshots still showed b24, so they should not
  be used to judge the exact b25 gutter thickness. Use deployed b25 visual QA for that.
- **P2 profile color:** the review follows `docs/PiPlay_UI_Priority_Improvements.md`, which says
  profile color should become the global accent. Current spec/code intentionally keep profile color as
  identity-only and global app accent as the app accent. This is an owner/stakeholder decision gate, not
  a code defect.
- **P3 transparency:** the current feature is honestly closer to "whole popout opacity" than
  video-safe transparency. A real chrome-only transparency model likely needs a windowing/composition
  design, not only a Settings rename.
- **P4 playback-state preservation:** timestamp/video-id plumbing exists, but volume/mute/speed and
  popout-side paused state require expanding DOM capture and return commands. Treat this as a real
  implementation plan, not a label-only change.

## Disposition

| Review item | Disposition | Next action |
|---|---|---|
| P1 borderless | Accept b25 as a useful cleanup, not complete. | Visual QA deployed b25 at 100/125/150 percent DPI before any deeper windowing work. Do not blindly reduce the 4 DIP band to 0. |
| P2 profile color global accent | Decision conflict. | Keep current identity-color implementation unless owner explicitly reverses the settled spec. |
| P3 transparency scope | Valid gap. | Rename/currently frame as whole-popout opacity, then separately spec chrome/background-only transparency. |
| P4 bring video back | Highest-value functional gap. | Plan and implement true dock/undock return with fresh return-state capture. |
| P5 video area utilization | Valid product gap. | Add after P4/P1: explicit Fit Window, Fill/Crop, Cinema Padding model. |
| P6 auto-hide chrome | Partial, lower urgency. | Leave behind P4/P3/P7 unless owner reprioritizes immersive main-window mode. |
| P7 rounded corners | Valid language/architecture gap. | Either expose only native DWM modes or write an ADR for WebView2/composition lift. |
| P8 unified main/popout | Dependent. | Falls out of P2/P3/P4/P5/P7 decisions. |

## Recommended Order

1. **P4 Bring video back.** This is the biggest user-visible behavior gap and does not depend on the
   WebView2 corner/transparency architecture.
2. **P1 visual QA.** Decide whether the 4 DIP band is visually acceptable in the deployed Stable copy.
3. **P3 opacity semantics.** Stop treating whole-window opacity as the final transparency feature.
4. **P2 decision gate.** Confirm whether owner wants to reverse the implemented profile-identity split.
5. **P7 honest corner model.** De-duplicate Soft/Round at the outer-window level or plan a real lift.
6. **P5 video fit model.** Add Fit/Fill/Cinema Padding once return behavior and visual frame decisions
   are stable.
